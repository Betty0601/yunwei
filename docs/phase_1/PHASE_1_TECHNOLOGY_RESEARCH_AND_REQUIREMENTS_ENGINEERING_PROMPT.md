本文档是**供后续 AI 执行阶段 1 工作的完整提示词文档**。它定义任务范围、执行方法、交付物格式、严禁事项和质量门禁。

### 1.2 项目定义（必须牢记）

**一句话定义**：专业级深层肌肉机械刺激仪，由电机驱动治疗头产生周期性机械冲击或振动，通过直接物理接触向目标肌肉组织传递机械能的治疗设备。

**工作原理边界**（违反即越界）：

| 类别 | 项目 | 本项目是否纳入 |
|------|------|----------------|
| 动力源 | 电机（电动执行器，含有刷/无刷/步进/伺服） | ✅ 纳入 |
| 动力源 | 气动压力波发生器 | ❌ 排除 |
| 动力源 | 电磁线圈/电磁冲击 | ❌ 排除 |
| 动力源 | 压电陶瓷超声换能器 | ❌ 排除 |
| 能量形式 | 直接机械接触 | ✅ 纳入 |
| 能量形式 | 声波（>20kHz 超声治疗） | ❌ 排除 |
| 能量形式 | 电流（EMS/TENS 电极刺激） | ❌ 排除 |
| 运动形式 | 周期性冲击或振动（由电机→运动转换机构→治疗头） | ✅ 纳入 |
| 治疗头接触 | 固体接触头（硅胶/塑料/金属等） | ✅ 纳入 |

### 2.3 缺失文件处理规则

如果某份输入文件**不存在或无法读取**：

1. 在输入登记表上标记 `[MISSING]`
2. 执行 AI 暂停，继续下一份检查（不要阻塞全部工作）
3. 检查结束后，将所有缺失文件汇总到一个"缺口清单"
4. 缺口清单作为阶段 1 启动受阻项，写入 `docs/stage1/gaps/input_gaps.md`
5. P0 优先级文件缺失时，必须向"发起人"报告；P1 优先级文件缺失时，执行 AI 可继续但需在最终报告中声明
6. **严禁自行创建缺失的阶段 0 文件**——阶段 0 文件只能由阶段 0 的责任人创建

### 2.4 矛盾输入处理规则

如果发现多份文件之间存在矛盾（例如 DMS_PR-001 说"目标市场是康复科"而 DMS_DEC-001 D-001 说"目标市场尚未确定"）：

2. 不自行决定哪份正确
3. 将矛盾点加入 DMS_DEC-001 待确认列表（如果有新 D-xxx 编号空间）
4. 继续执行研究，但在引用该矛盾点时必须标注"⚠️ 待发起人决策"
5. 所有矛盾必须在 PRS V1.0 冻结前得到解决或明确取舍

### 3.3 医疗/治疗用途的特殊影响

产品预期用于"治疗"或"康复"而非"健身放松"时，以下方面会受到显著影响，执行 AI 必须在产品定义中明确：

| 方面 | "治疗/康复"定位的影响 |
|------|----------------------|
| 分类 | 可能纳入医疗器械监管范围 |
| 合规 | 需要注册申报、风险管理文件、验证测试 |
| 证据 | 疗效声明需要临床证据支撑（V1 阶段不做临床） |
| 验证 | 每项安全和性能要求都需要可追溯的验证记录 |
| 材料 | 人体接触材料需要生物相容性评估（ISO 10993） |
| 输出限值 | 治疗输出参数需要基于临床合理性确定，不能拍脑袋 |
| 标识 | 标签、说明书、禁忌提示需要严格合规 |

### 3.4 严禁事项（产品定义）

| 严禁 | 为什么严禁 | 正确做法 |
|------|-----------|----------|
| ❌ 凭产品名称直接认定分类（比如"筋膜枪=非医疗器械"） | 分类取决于实际治疗用途和声称效果，不是产品名称 | 基于目标市场的法规对"按摩设备"vs"治疗设备"的定义来判定 |
| ❌ 凭"能治疗肌肉酸痛"就宣称有疗效 | 疗效需要临床证据，阶段 1 没有临床数据 | 使用"缓解肌肉紧张""促进血液循环"等更保守的描述 |
| ❌ 假设用户是"康复师"就默认能做复杂参数调整 | 康复师也可能不会用复杂设备，误操作会有安全风险 | 对每类用户做"操作能力画像"，区分专业能力等级 |
| ❌ 使用"所有运动员""所有康复师"这种绝对化表述 | 每个细分人群需求不同 | 按具体细分（ elite 职业运动员 vs 大学生运动员；专业康复师 vs 社区康复师） |
| ❌ 假设用户能读懂所有技术参数（如"冲程 12mm""扭矩 1.5N·m"） | 大多数用户只关心"档位 1-5" | 用户界面用简单档位，详细参数放说明书 |

### 4.3 严禁事项（技术路线）

| 严禁 | 为什么严禁 | 正确做法 |
|------|-----------|----------|
| ❌ 因为某方案"市场上常见"就直接判定为最佳 | 常见不代表适合本项目目标。竞品可能因为成本/供应链/法规原因选了某个方案，不一定是最优工程解 | 对每条路线都做 14 项完整记录后再对比 |
| ❌ 跳过数学计算，仅凭直觉定参数 | 冲程、频率、冲击力度之间有严格关系（如冲击力 ≈ m·a，而振动加速度 a = (2πf)²·A，A 是振幅） | 用工程公式做至少一阶估算，并把计算过程记录到证据中 |
| ❌ 只写"优点"，回避或轻描淡写"缺点" | 所有技术路线都有关键 trade-off，隐瞒缺点会导致阶段 2 选错 | 缺点和优点篇幅相当，至少各 2 条 |
| ❌ 引用竞品宣传但标注为"实测数据" | 竞品宣传的参数常有水分，特别是冲击力和频率 | 区分"竞品宣传值"和"工程计算值"和"已证实实测值" |
| ❌ 在阶段 1 就冻结具体电机型号/轴承型号 | 阶段 2 才做详细设计，冻结型号需要 BOM 级决策 | 阶段 1 到"电机类型"级即可（如"无刷直流 24V 外径约 40mm"），不要到具体型号 |
| ❌ 用"应该""大致""差不多"这种模糊词 | 阶段 1 要的是工程输入，模糊词会污染后续设计 | 用数值范围（如"12-16mm 冲程"）、用"理论值 15mm" |

### 4.5 运动转换机构重点分析（强制覆盖）

这是本产品最核心的技术领域之一，必须重点分析以下 4 种常见方案：

| 方案 | 运动形式 | 关键参数关系（需要计算） |
|------|----------|------------------------|
| 偏心块 + 电机 | 旋转振动（治疗头做圆周平面内椭圆运动） | 振动频率 = 电机转速/60；振幅 = 偏心距 m = m_offset · ω² · r |
| 曲柄滑块 | 直线往复冲击（治疗头做前后直线运动） | 冲程 = 2r（曲柄半径）；冲击频率 = 电机转速/60（需换向机构） |
| 凸轮 + 顶杆 + 复位弹簧 | 周期性冲击（治疗头被凸轮顶出，弹簧缩回） | 冲击频率 = 电机转速/（凸轮齿数）；冲程 = 凸轮升程 |
| 齿轮 + 连杆 + 偏心轴 | 复合运动（平面内椭圆 + 小幅度冲击） | 运动轨迹 = 偏心轴 + 连杆参数共同决定 |

对每一种，都必须用 Fusion 360 的参数化建模能力（阶段 1 可以只做运动学仿真、不冻结尺寸）验证理论分析是否成立。

## 章节 7：需求工程与需求分解

### 7.1 18 个需求领域清单（全部必须覆盖）

执行 AI 必须在 PRS 中对以下 18 个领域逐一建立需求条目，每个领域至少 3 条需求。

| # | 需求领域 | 典型需求内容 |

| 1 | **用户需求 (User Requirements)** | 用户希望产品实现什么功能、解决什么问题 |

| 5 | **运动机构需求** | 运动转换机构类型、冲击/振动幅度 |
| 6 | **电机驱动需求** | 电机类型、电压、功率、控制精度、调速范围 |
| 7 | **控制与反馈需求** | 控制方式、档位数量、反馈类型（温度/电流/力） |
| 8 | **电气与供电需求** | 输入电压、电池容量、充电时间、续航时间、保护电路 |
| 9 | **结构与材料需求** | 外壳材料、接触头材料、支撑结构、防护等级 |

| 12 | **人机交互需求** | UI 界面、操作反馈（灯光/声音）、误操作防护 |
| 13 | **可靠性需求** | 寿命目标（如 ≥ 5000 小时）、MTBF、失效率 |
| 14 | **维护与清洁需求** | 接触头可更换、外壳可擦拭、内部防水等级 |
| 15 | **环境适应性需求** | 工作温度范围、存储温度、湿度、海拔、振动/冲击 |
| 16 | **可制造性需求** | 装配公差、标准件比例、采购可行性 |
| 17 | **验证与测试需求** | 每条性能需求对应的验证测试方法 |
| 18 | **文档与追踪需求** | 设计历史文件 (DHF)、需求追踪矩阵 (RTM)、合规文档 |

### 7.2 需求编号规则

执行 AI 在给需求编号时，必须遵循以下前缀约定：

| 前缀 | 全称 | 适用场景 | 示例 |
|------|------|----------|------|
| **USR** | User Requirement | 用户原始需求（URD 中） | USR-001 |
| **REQ** | Product Requirement | PRS 中的产品级需求 | REQ-001 |
| **CON** | Constraint | 外部约束（标准/法规/供应链/成本） | CON-001 |
| **INT** | Interface | 外部/内部接口需求 | INT-001 |
| **SAF** | Safety | 安全相关需求（优先最高） | SAF-001 |
| **VER** | Verification | 验证测试需求（与一条或多条 REQ 关联） | VER-001 |
| **EVD** | Evidence | 证据编号（与章节 6 共用同一编号空间） | EVD-001 |
| **RISK** | Risk | 风险登记编号（与章节 9 共用同一编号空间） | RISK-001 |
| **TBD** | To Be Determined | 待定项（阶段 1 无法确定，需要后续阶段解决） | TBD-001 |
| **DEC** | Decision | 决策登记（与 DMS_DEC-001 共用编号） | D-001 |

### 7.3 单条需求 15 项必填字段

每一条需求，不管是 USR、REQ、CON、SAF 还是其他，必须填写以下 15 项信息。**缺项不得进入 PRS**：

| # | 字段 | 说明 | 是否必填 |
|---|------|------|----------|
| 1 | **需求编号** | 如 REQ-042 | ✅ |
| 2 | **需求名称 / 标题** | 简短描述 | ✅ |
| 3 | **需求类型** | USR / REQ / CON / INT / SAF / VER / RISK | ✅ |
| 4 | **所属领域** | 章节 7.1 的 18 个领域之一 | ✅ |
| 5 | **优先级** | P0（必须有）/ P1（应该有）/ P2（可以有） | ✅ |
| 6 | **完整描述** | 需求的文字描述，包含"必须/应当/可以"关键词 | ✅ |
| 7 | **量化阈值或范围** | 有数值的写数值（如"频率 20-50Hz"），无数值的写 TBD | ✅ |
| 8 | **来源** | USR-xxx / 标准 / 法规 / 专家判断 / 竞品对比 / 其他 | ✅ |
| 9 | **证据支持** | EVD-xxx 引用 | ✅（至少 1 条，TBD 可无） |
| 10 | **关联风险** | RISK-xxx 编号 | ⚠️ 有则必填 |
| 11 | **假设/前提** | 该需求成立的前提条件 | ⚠️ 有则必填 |
| 12 | **验收条件 (Acceptance Criteria)** | 可测试、可量化、可判定的验收标准 | ✅ |
| 13 | **验证方法** | 测试 / 仿真 / 检查 / 演示 / 评审 | ✅ |
| 14 | **当前状态** | Draft / Reviewed / Approved / Deferred / TBD | ✅ |
| 15 | **备注 / 待决事项** | 任何需要说明的补充 | ⚠️ 有则必填 |

### 7.4 量化阈值处理规则

| 情况 | 处理方式 | 示例 |
|------|----------|------|
| 有充分工程/实验证据支撑 | 冻结具体数值或小范围 | "频率必须 ≥ 25Hz（EVD-042 电机手册）" |
| 有方向但无精确数值 | 给出合理范围 | "冲程应在 6-12mm 之间（USR-015 用户反馈）" |
| 完全无证据 | 标记 TBD + 进入 DEC | "最大冲击力 TBD（待阶段 3 测试样机确定）" |
| 来自竞品宣传 | 标记"参考值"不冻结 | "竞品 X 宣传 15kg 冲击力，本项目目标待定" |
| 来自法规强制要求 | 冻结法规要求的数值 | "外壳表面温度 ≤ 43℃（IEC 60601-1 要求）" |

### 7.5 严禁事项（需求工程）

| 严禁 | 为什么严禁 | 正确做法 |
|------|-----------|----------|
| ❌ 把模糊表达当作工程需求（如"产品应该好用"） | 无法验收、无法测试 | 改成可测量的表达："用户连续使用 10 分钟后双手握持处温度不超过 38℃" |
| ❌ 每条需求没有"验收条件"就写入 PRS | 验收条件是阶段 5/6 验证的依据，缺失会导致无法验证 | 每条 REQ 都要配一个 VER-xxx，明确"测什么、怎么测、通过标准是什么" |
| ❌ 需求之间出现矛盾不处理 | 矛盾的需求无法同时满足 | 建立需求追踪矩阵（RTM）时，发现矛盾立即标记并升级 |
| ❌ 把阶段 2 才需要冻结的具体设计参数（如"用 2 个 M4 螺钉固定"）当作阶段 1 需求 | 阶段 1 需求是"做什么"不是"怎么做" | 阶段 1 写"电机安装必须可靠固定，抗震 10g 不松动"，具体螺钉数量阶段 3 决定 |
| ❌ 没有来源的"拍脑袋"需求 | 无法追溯为什么要这个需求 | 每条需求的"来源"字段必须有值 |
| ❌ 需求编号重复 | 追踪时混乱 | 用全局唯一编号空间，每加一条递增 |
| ❌ 把"希望"和"必须"混为一谈 | 优先级模糊，后续无法取舍 | 用"必须/应当/可以"三个层级 + P0/P1/P2 双标记 |

### 8.4 严禁事项（参数）

| 严禁 | 为什么严禁 | 正确做法 |
|------|-----------|----------|
| ❌ 在阶段 1 就填"最终尺寸/性能数值"（如"冲程 = 10.5mm"） | 阶段 2/3 才会通过计算和仿真确定具体值，阶段 1 定值会阻塞设计迭代 | 阶段 1 填范围（如"8-12mm"）或候选值（如"方案 A: 10mm, 方案 B: 12mm"） |

## 章节 9：初步风险与法规识别

### 9.1 17 类风险清单（全部必须覆盖）

执行 AI 必须对以下 17 类风险逐一登记，每类至少 1 条具体风险。登记位置：`docs/stage1/risk/RISK_REGISTER.md`

| # | 风险类别 | 典型触发情景 |
|---|----------|-------------|
| 1 | **机械冲击风险** | 冲击力度过大损伤人体组织、治疗头脱落造成伤害 |
| 2 | **运动幅度异常** | 冲程超过设计值、治疗头与外壳碰撞 |
| 3 | **运动卡滞** | 轴承咬死、齿轮卡齿、凸轮磨损导致冲击机构卡死 |
| 4 | **疲劳断裂** | 曲柄/连杆/偏心轴在循环应力下疲劳断裂 |
| 5 | **夹伤风险** | 运动部件与外壳之间缝隙夹手 |
| 6 | **部件松脱** | 螺钉松动、齿轮轴脱出、轴承移位 |
| 7 | **电机过载** | 电机堵转、电流超额定值、绕组烧毁 |
| 8 | **过热风险** | 电机/驱动板/外壳温度超过安全限值 |
| 9 | **噪声风险** | 高频/高强度使用导致噪声过大影响用户/他人 |
| 10 | **电气故障** | 短路、漏电、电池起火、充电器故障 |
| 11 | **控制器失效** | MCU 死机、固件崩溃、调速失灵 |
| 12 | **误操作** | 用户误开最高档、小孩误触、操作界面错误反馈 |
| 13 | **清洁不当** | 液体进入内部、接触头未消毒、外壳积灰 |
| 14 | **材料接触风险** | 接触材料引起皮肤过敏/不适、材料在高温下释放有害物质 |
| 15 | **制造偏差** | 关键部件公差超差、装配错误、漏装 |
| 16 | **运输风险** | 运输过程中剧烈振动/冲击导致内部损坏 |
| 17 | **维护风险** | 用户自行拆解、错误更换部件、电池更换不当 |

### 9.2 每项风险记录要求（7 字段）

| # | 字段 | 说明 |
|---|------|------|
| 1 | **风险编号** | RISK-001, RISK-002 ... |
| 2 | **风险描述** | 一句话描述具体风险（不要泛泛而谈"过热"） |
| 3 | **根本原因** | 触发这个风险的根本原因（设计缺陷/材料问题/使用不当/制造偏差） |
| 4 | **后果严重程度** | 高（伤害人体）/ 中（损坏设备/影响使用）/ 低（轻微影响） |
| 5 | **证据支持** | EVD-xxx 引用（来自竞品问题、标准规定、工程理论） |
| 6 | **已考虑的控制措施（初步）** | 阶段 1 能想到的缓解方向（不是详细方案） |
| 7 | **未解决问题 / 后续阶段需要做什么** | 哪些信息缺失、需要哪个阶段验证 |

**示例**：
```
| RISK-005 | 夹伤风险：运动部件与外壳间缝隙可能夹住手指 | 运动部件与外壳设计间隙过大 | 高 | EVD-067（ISO 13857 缝隙安全标准） | 控制缝隙 ≤ 8mm 或 ≥ 18mm | 需要阶段 3 详细尺寸确定后验证 |
```

### 9.3 安全阈值的严禁事项

| 严禁 | 为什么严禁 | 正确做法 |
|------|-----------|----------|
| ❌ 无依据地制定治疗输出限值（如"冲击力不能超过 15kg"） | 不同部位、不同用户、不同治疗场景的安全限值不同；拍脑袋定限可能限制了合理使用或放过了真正危险值 | 安全阈值要来自法规（IEC 60601-1 外壳温度 ≤ 43℃）、来自已发表的医学研究、或标记 TBD 需要临床验证 |
| ❌ 说"这个风险很小所以可以不记录" | 即使小风险也要登记、评估、跟踪 | 17 类风险每类至少 1 条，登记后标"低严重度、低发生概率" |
| ❌ 只记录物理伤害风险，忽略软件/控制/误操作风险 | 控制器失效可能导致电机失控，后果可能比机械失效更严重 | 17 类全部覆盖，包括控制、误操作、清洁 |
| ❌ 控制措施写"加强质量控制"这种空话 | 没有可执行的方向 | 写"接触头与外壳缝隙 ≤ 8mm（ISO 13857）"这种具体方向 |

### 9.4 法规研究边界

执行 AI 在法规研究时，必须理解以下边界：

| 可以做 | 不能做 |
|--------|--------|
| ✅ 列出目标市场的适用法规/标准清单（带编号、标题、版本） | ❌ 给出正式的合规性声明（需要测试数据支撑） |
| ✅ 根据产品初步定义，推测可能的分类（如中国 NMPA 二类） | ❌ 在正式分类确认前，把推测当定论 |
| ✅ 说明满足某项标准需要做哪些测试 | ❌ 说"我们设计就满足标准"（标准要求的是测试结果，不是设计意图） |
| ✅ 列出中/美/欧三大市场的关键法规差异 | ❌ 给出"哪个市场最容易准入"的结论（需要综合成本/时间/市场考量） |
| ✅ 引用法规中的具体条款号 | ❌ 自己编造条款号或内容 |

### 9.5 目标市场与分类研究指引

| 市场 | 主管机构 | 可能的分类 | 关键法规 |
|------|----------|-----------|----------|
| **中国** | NMPA 国家药监局 | 一类（无源按摩器械）/ 二类（电动按摩器械）/ 可能三类（如有治疗声称） | 《医疗器械监督管理条例》、GB 9706.1（对应 IEC 60601-1）、GB/T 16886（生物相容性） |
| **美国** | FDA | 510(k) 或 De Novo（按摩设备通常低风险） | 21 CFR Part 890（物理医学设备）、FDA 指南"Massage Devices" |
| **欧盟** | 各成员国主管机构 | MDR 分类规则下的低风险类 | 欧盟 MDR 2017/745、IEC 60601-1（EN 版本）、CE 认证路径 |

**关键提醒**：
- 产品分类不是看"叫什么名字"，而是看"预期用途"和"技术特征"
- 同一个产品在不同市场的分类可能不同
- "声称治疗"会显著提高分类等级和合规要求

### 9.6 风险登记与 DMS_RSK-001 联动

阶段 0 已有 DMS_RSK-001 初始风险登记。阶段 1 识别的风险必须：
1. 编号延续 RISK-xxx（从 RISK-001 开始，不与 DMS_RSK-001 冲突）
2. 每完成一类风险识别后，更新 DMS_RSK-001（或在其中增加引用）
3. 所有风险在阶段门 G1→G2 时必须有人负责跟踪
