# DMS-P2-09 Fusion 360 总装架构与概念建模实施规范

## 1. Fusion 360 使用原则

Fusion 360 在本项目中承担参数化机械设计、装配关系定义、几何检查、运动关系检查、工程图和制造数据准备等工作。**它不是产品可行性的自动证明工具。**

必须区分四类工作：
1. **几何建模** — 零件的形状与尺寸是否符合定义
2. **装配运动** — 组件之间的约束是否允许预期运动
3. **工程分析** — 载荷、强度、热、疲劳和动态响应是否满足要求
4. **实体验证** — 实际零件与整机在真实工况下是否符合要求

某个功能在 Fusion 360 中是否可用，取决于实际版本、许可、API 能力和当前文档环境。不能假设所有动力学、接触冲击、疲劳和控制分析均能通过基础装配功能完成。

## 3. CAD 文件管理策略

Fusion 360 原生设计文件不应当被当作普通文本文件进行差异合并。采用双重管理：
- 使用 **Fusion 360 自身的数据管理与版本能力** 保存 CAD 设计历史
- 使用 **Git** 管理参数定义、脚本、任务包、分析代码、文档和测试记录
- 使用 **GitHub Issue** 关联设计任务
- 使用受控发布记录关联 CAD 版本与验证结果

### CAD 修改记录字段

每次 CAD 修改应记录：

| 字段 | 要求 |
|---|---|
| CAD Task ID | 唯一任务编号 |
| 需求编号 | 关联正式需求 |
| 输入基线 | 修改前的 CAD 版本 |
| 参数基线 | 使用的参数文件版本 |
| 执行工具版本 | Fusion 版本、插件或脚本版本 |
| 修改对象 | 组件与零件清单 |
| 实际修改 | 参数、特征和装配关系变更 |
| 检查结果 | 几何、运动、干涉和其他适用检查 |
| 输出版本 | 修改后的 CAD 版本 |
| Git Commit | 对应代码或文档提交 |
| GitHub Issue | 关联任务 |
| 审核状态 | 待审核、通过、退回或暂停 |

**不能只保存一张模型截图作为修改完成的唯一证据。**

## 4. 概念总装的建模顺序（CAD-01 ~ CAD-06）

### CAD-01：创建项目与总装骨架
**任务目标**：建立顶层设计文档、创建顶层组件树、建立统一坐标系、建立主要装配基准、创建必要的参考几何、记录设计基线。

**验收要求**：
- 顶层总装名称正确
- 坐标系定义清楚
- 主要基准有明确用途
- 组件层级与架构文件一致
- 不存在未说明的隐式依赖

### CAD-02：建立运动链概念模型
根据候选方案分别建立可替换的概念组件：偏心机构概念模型、曲柄连杆概念模型、凸轮机构概念模型、直线直驱概念模型。

**不建议把所有候选方案同时混入一个复杂总装** — 可以通过独立设计分支或独立候选文件分别研究，避免错误的组件关系互相污染。

**验收要求**：每种机构均具有清晰的输入与输出定义、自由度符合预期、运动极限位置可识别、关键运动尺寸由参数驱动、运动关系可以复核、不存在未说明的固定或接地组件。

### CAD-03：建立输出杆与导向系统
建立输出杆的基准轴线、导向件与支撑件、必要的运动副；检查行程范围和导向与输出杆的几何关系。

**验收要求**：
- 输出杆在预期方向上具有正确运动自由度
- 不存在不必要的旋转或侧向自由度
- 极限位置有明确参考
- 导向长度、支撑跨距和配合参数有来源
- 相关零件没有因几何重叠而产生虚假的干涉结论

### CAD-04：建立治疗头组件
定义输出接口、建立治疗头连接座、定义防脱结构、建立可更换附件的概念接口。

**验收要求**：连接基准明确、治疗头与输出杆的相对位置可追踪、防脱和拆装结构可识别、质量和惯量可在参数确定后计算、任何接触表面参数均标注为待确认或正式输入。

### CAD-05：建立驱动与支撑结构
安装电机或直线执行器的概念占位组件、建立驱动轴和支撑位置、定义关键连接基准、检查运动链空间布局。

**验收要求**：
- 电机与机构接口一致
- 轴线或安装方向明确
- 运动包络不与支撑结构产生不合理干涉
- 维修和装配工具空间得到初步检查
- **未经批准的电机型号和尺寸不被当作正式选型**

### CAD-06：建立机架与外壳包络
在运动链和关键接口明确后，再建立主机架、电机安装支架、轴承支撑件、外壳概念包络、握持区域、线缆出口、检修区域。

**验收要求**：
- 外壳不与正常运动包络冲突
- 关键紧固件可达
- 维护通道可识别
- 线缆不会穿越危险运动区域
- 热管理所需空间得到预留
- **外观造型没有覆盖尚未解决的结构问题**

## 5. 参数化建模规范

### 参数命名前缀

| 前缀 | 含义 |
|---|---|
| `IN_` | 正式输入 |
| `DRV_` | 驱动参数 |
| `KIN_` | 运动学参数 |
| `DYN_` | 动力学参数 |
| `STR_` | 结构参数 |
| `THM_` | 热参数 |
| `ASM_` | 装配参数 |
| `ENV_` | 环境与包络参数 |
| `TMP_` | 临时概念参数 |

例如 `KIN_Stroke` 可以作为行程参数名称，但在正式输入批准之前，它只能是参数名，不能自动代表已确定的行程值。

### 参数依赖原则
- 一个关键设计输入应有一个正式来源
- 派生参数优先通过公式计算
- 避免在多个零件中重复写入同一个未经关联的数值
- 避免多个参数形成无法解释的循环依赖
- 修改参数后，应检查所有依赖组件
- 重要参数应与参数字典编号关联
- 临时参数必须在模型和交付文件中显式标识
- 冻结参数必须有批准记录

### 草图与特征规范
- 尽量以原点、基准面和稳定参考几何建立草图
- 为关键草图建立明确的几何约束和尺寸约束
- 避免依赖易变的临时边线或不稳定的面引用
- 特征命名应反映工程功能，而不是只使用默认序号
- 关键尺寸应由参数驱动
- 对于概念布局，可使用简化几何，但必须标记为非制造几何
- 对于后续制造零件，应在详细设计阶段补齐公差、材料和工艺要求

## 6. 装配与运动副规范

装配模型应明确：
- 哪些组件固定、哪些旋转、哪些直线移动、哪些同时具有旋转和平移
- 哪些组件之间存在相对运动
- 哪些自由度由机构本身约束、哪些由独立导向件约束
- 哪些运动范围受到机械限位
- 哪些运动参数用于驱动动画或运动研究

例如：电机定子或安装座可作为机架参考组件，电机转子或驱动轴应具有符合机构原理的旋转关系，偏心件应与驱动轴建立明确的相对关系，输出杆应通过相应的导向关系限制非期望运动，治疗头应与输出杆建立明确的连接关系。

**具体关节类型必须依据真实机构确定，不能为了让动画运行而添加与实际机械结构不一致的约束。**

```yaml
task_id: DMS-CAD-001

  cad_version: TBD
  parameter_version: TBD

  - REQ-ID-TBD

inputs:
  - file: TBD
    version: TBD
    status: TBD

approved_parameters: []

  - name: TBD
    purpose: conceptual_layout_only

scope:
  included:
    - top_level_assembly
    - candidate_motion_chain
  excluded:
    - final_motor_selection
    - final_contact_force_design
    - production_release

  - create_components
  - define_reference_geometry
  - define_joints
  - inspect_motion_envelope

  - component_tree_matches_architecture
  - required_degrees_of_freedom_verified
  - no_unexplained_interference
  - all_temporary_parameters_identified

  - cad_document

  - preserve_previous_baseline
  - record_failed_operation

  - request_approval_for_scope_change
```

这是建议格式，不代表当前已存在可直接运行的自动化系统。实际字段和脚本接口需要根据 Fusion 360 API、MCP 服务及项目工具链进行验证。

## 8. Fusion 360 API/MCP 能力验证（API-01 ~ API-12）

正式让 AI 修改工程模型之前，应先执行一组小规模的接口测试。

| 测试编号 | 测试内容 | 通过证据 |
|---|---|---|
| API-01 | 检查 Fusion 版本与运行环境 | 记录实际版本与环境 |
| API-02 | 读取当前设计文档 | 返回正确文档标识与状态 |
| API-03 | 读取组件树 | 返回可核验的组件名称和层级 |
| API-04 | 读取参数 | 返回参数名称、数值和单位 |
| API-05 | 创建测试组件 | 组件出现在实际文档中 |
| API-06 | 创建测试草图与特征 | 几何可检查、操作有日志 |
| API-07 | 修改测试参数 | 修改前后数值与几何变化一致 |
| API-08 | 读取装配关系 | 返回实际关节与约束信息 |
| API-09 | 检查测试几何 | 返回可核验的几何检查结果 |
| API-10 | 导出测试文件 | 文件存在、格式正确且可重新打开 |
| API-11 | 故障处理 | 失败被记录，基线不被无意破坏 |
| API-12 | 权限与审批 | 未批准操作被阻止或转入人工审批 |

**必须注意**：一个测试通过，不意味着整个接口具备所有 CAD 操作能力。在执行自动化前，还应验证文档锁定、并发编辑、保存失败、网络断开、工具调用超时和模型状态不一致等情况。
