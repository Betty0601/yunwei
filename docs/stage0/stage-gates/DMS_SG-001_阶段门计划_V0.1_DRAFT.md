## 1. 阶段门方法论

### 1.1 核心原则

阶段门（Stage-Gate）是一种结构化的研发管理方法。每个阶段（Stage）是一组并行执行的活动，每个门（Gate）是一个决策检查点，只有满足所有进入条件并交付必需输出，项目才能进入下一阶段。

### 1.2 本项目的 8 个阶段门

```
门 0 → 阶段 0 → 门 1 → 阶段 1 → 门 2 → 阶段 2 → 门 3 → 阶段 3
(G0) (S0)      (G1)   (S1)      (G2)   (S2)      (G3)   (S3)

门 4 → 阶段 4 → 门 5 → 阶段 5 → 门 6 → 阶段 6 → 门 7 → 阶段 7
(G4)   (S4)      (G5)   (S5)      (G6)   (S6)      (G7)   (S7)
```

| 门 | 阶段 | 阶段名称 | 核心活动 |
|----|------|----------|----------|
| G0 | S0 | 项目定义与研发管理体系 | 建立治理、WBS、AI 协作、版本管理、风险框架 |
| G1 | S1 | 市场/技术/法规研究与产品需求 | 用户画像、竞品分析、法规标准、专利扫描、PRS |
| G2 | S2 | 系统设计与技术方案 | 系统架构、动力选型、电气架构、系统 FMEA |
| G3 | S3 | 详细设计与 CAD 建模 | 零件设计、装配体、工程图、公差链、材料选择 |
| G4 | S4 | 验证主计划与 DFM | 验证计划、测试用例、DFM 分析、供应商评估 |
| G5 | S5 | 验证、试产与设计确认 | 样机试制、测试执行、确认报告、DHF 构建 |
| G6 | S6 | 生产工艺与注册准备 | BOM final、工艺文件、注册资料 |
| G7 | S7 | 项目关闭与归档 | 产品发布支持、经验教训、归档 |

### 1.3 门的决策输出

每个阶段门必须产出以下三种决策之一：

| 决策 | 含义 |
|------|------|
| ✅ **GO** | 满足所有条件，放行进入下一阶段 |
| ⚠️ **CONDITIONAL GO** | 有条件放行，必须在规定时间内满足整改项 |
| ❌ **NO-GO** | 不满足条件，打回上阶段修改或终止项目 |
