## 1. 产品定义

### 1.1 一句话定义

**专业级深层肌肉机械刺激仪：由电机驱动治疗头产生周期性机械冲击或振动，通过直接物理接触向目标肌肉组织传递机械能的治疗设备。**

### 1.2 核心技术特征（已证实事实）

以下事实已经过 BASELINE-001 验证或可从公开工程原理确定：

| 编号 | 特征 | 事实来源 |
|------|------|----------|
| F-01 | 动力源为电机（电动执行器） | 排除气动、电磁线圈、压电陶瓷等替代方案 |
| F-02 | 治疗头做周期性机械运动（冲击式/振动式） | 运动形式由凸轮/偏心块/曲柄滑块机构实现 |
| F-03 | 机械能通过固体接触传递至人体 | 非声、电、气能量形式 |
| F-04 | 设备为手持或固定支撑结构 | 操作形式待阶段 2 确定 |

### 1.3 待工程确定的设计输入（非冻结）

以下内容**尚未确定**，将在阶段 1-3 通过研究与设计逐步明确：

- [ ] 目标市场（专业康复/运动训练/家庭消费）
- [ ] 产品定位（入门/中端/高端）
- [ ] 治疗头数量与类型
- [ ] 频率范围、冲击力范围、行程范围
- [ ] 供电方式（市电/锂电/可更换电池）
- [ ] 控制系统复杂度（机械旋钮/MCU 数字控制/APP 互联）
- [ ] 材料选择（接触头/外壳/结构件）
- [ ] 重量与尺寸约束
- [ ] 使用寿命目标
- [ ] 法规合规路径（NMPA/FDA/CE）

## 2. 纳入边界 (In-Scope Boundaries)

### 2.1 功能边界

| 功能域 | 纳入内容 | 阶段 |
|--------|----------|------|
| 机械能生成 | 电机 + 运动转换机构 + 治疗头 | S2-S3 详细设计 |
| 人机交互 | 手持握持结构、操作界面（初定） | S3 |
| 动力系统 | 电机选型、传动设计、供电方案 | S2-S3 |
| 支撑防护 | 外壳、防尘、防误触 | S3 |
| 基本控制 | 启停、档位调节 | S3-S4 |
| 安全保护 | 过流、过热、接触力过载 | S4 |
| 可制造性 | 装配、维护、寿命设计 | S5 |
| 验证确认 | 性能测试、安全测试、可靠性 | S5-S6 |

### 2.2 交付物边界

本项目最终预期交付：

1. 生产级 CAD 模型与工程图纸（原生 Fusion 360 格式）
2. 固件源码与硬件 BOM
3. 设计历史文件 (DHF) 与设计主记录 (DMR)
4. 合规性文档（风险管理文件、验证报告）
5. 试制/小批量生产的工艺文件

## 3. 排除边界 (Out-of-Scope Boundaries)

### 3.1 技术排除（领域边界）

| 排除项 | 理由 |
|--------|------|
| 气动压力波系统（pneumatic shockwave） | 动力源类型不符本项目定位 |
| 超声治疗头（piezoelectric transducer） | 能量形式为声波，非直接机械接触 |
| EMS/TENS 电极刺激模块 | 能量形式为电流，与机械刺激无直接关联 |
| 激光/红外辅助治疗 | 可作为未来扩展，但不在当前范围 |
| 智能生物反馈（肌电/加速度传感器闭环） | 属智能增强版，V1 暂排除 |

### 3.2 产品排除（阶段边界）

| 排除项 | 说明 |
|--------|------|
| 消费级玩具/筋膜枪低配版本 | 明确"专业级"定位，瞄准康复/运动领域 |
| 大型理疗床/固定支撑系统 | V1 聚焦手持便携设备 |
| 云端互联/大数据平台 | V1 无联网要求 |
| 全自动治疗程序编排 | V1 以手动操作为主 |

### 3.3 本阶段排除（阶段 0 边界）

| 排除项 | 理由 |
|--------|------|
| 任何 CAD 参数化建模 | 阶段 0 不做产品设计 |
| 详细 BOM 或成本估算 | 缺乏设计输入 |
| 临床方案或疗效声明 | 无设计输出支撑 |
| 供应商谈判或 DFM | 设计未冻结 |

## 5. 假设与事实分类规则

### 5.1 分类定义

为确保研发过程中信息的可追溯性与区分度，所有项目信息必须明确归类为以下六种之一：

| 分类 | 符号 | 定义 | 可否作为设计输入 | 验证要求 |
|------|------|------|------------------|----------|
| **已证实事实** | 🔵 F | 已通过 BASELINE 或测试验证的客观信息 | ✅ 直接可用 | 无需额外验证 |
| **工程假设** | 🟡 A | 基于经验/文献的合理推测，待验证 | ⚠️ 有条件使用 | 必须在阶段 S2/S3 验证 |
| **待决事项** | 🔴 D | 尚未确定的关键决策点 | ❌ 不可使用 | 进入 DEC-001 跟踪 |
| **设计输入** | ⬅️ I | 外部输入的需求/约束/标准 | ✅ 可用但需评审 | 记录来源与版本 |
| **设计输出** | ➡️ O | 本项目产生的设计成果 | ✅ 可用（当前版本） | 需评审与冻结 |
| **验证结果** | ✅ V | 测试/仿真/评审的结果 | ✅ 依据充分即可用 | 记录测试条件 |

### 5.2 分类标注规范

所有技术文档中的关键信息必须带上分类符号与编号，例如：

```
电机选择 🟡 A-03（假设：无刷直流电机效率最优）
治疗头行程 ⬅️ I-12（输入：用户反馈 6-12mm 舒适范围）
```

### 5.3 假设管理规则

1. 所有 🟡 A 类假设必须登记在 DEC-001 或专项假设清单中
2. 假设的验证截止日期不得晚于相关设计冻结节点
3. 假设被证伪后，必须触发变更控制流程
4. 假设清单每次评审必须重新过一遍

## 6. 边界变更控制

### 6.1 边界变更触发条件

| 触发条件 | 处理 |
|----------|------|
| 纳入边界扩大 | 发起人审批 + 资源重估 + 阶段门更新 |
| 纳入边界缩小 | 发起人审批 + 影响评估（是否影响合规/核心目标） |
| 排除边界变更 | 发起人审批 + 技术路线评审 |
| 阶段边界变更 | 阶段门计划同步更新 |

### 6.2 边界对齐检查点

| 检查点 | 活动 |
|--------|------|
| 每次阶段门 | 回顾范围是否偏离 |
| 每次变更请求 | 评估是否影响边界定义 |
| 每次设计评审 | 核对当前设计是否在纳入边界内 |
