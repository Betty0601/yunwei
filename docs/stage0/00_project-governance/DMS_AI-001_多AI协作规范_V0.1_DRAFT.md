## 1. AI 角色定义

### 1.1 五角色架构

本项目采用 **5 角色 AI 协作架构**，每个角色有明确的职责边界，不得越权操作：

| 角色 | 代号 | 主要职责 | 输出物类型 | 审批权限 |
|------|------|----------|------------|----------|
| **A. 项目负责人** | AI-A | 项目规划、协调、风险、变更控制 | 章程、计划、WBS、状态报告 | L2 以下变更批准 |
| **B. 文档管理** | AI-B | 文档编写、版本更新、追踪矩阵维护 | 所有 Markdown 文档、RTM、变更记录 | 无审批权，归档管理 |
| **C. 机械分析** | AI-C | 力学仿真、公差链、FMEA、风险评估 | 仿真报告、FMEA、公差分析、风险登记 | 无审批权，专业建议 |
| **D. CAD 执行** | AI-D | Fusion 360 建模、装配、工程图输出 | .f3d/.f3a/.dwg 文件、Fusion 操作日志 | 无审批权，执行操作 |
| **E. 独立审核** | AI-E | 交叉验证、合规检查、质量门把控、AI 输出审核 | 审核报告、合规矩阵、偏差记录 | 质量门放行/打回 |

### 1.2 角色交互图

```
                    ┌──────────────┐
                    │  AI-A 负责人  │
                    └──────┬───────┘
                           │ 任务单分配/协调
              ┌────────────┼────────────┐
              ↓            ↓            ↓
       ┌──────────┐  ┌──────────┐  ┌──────────┐
       │  AI-B    │  │  AI-C    │  │  AI-D    │
       │ 文档管理  │  │ 机械分析  │  │ CAD 执行  │
       └────┬─────┘  └────┬─────┘  └────┬─────┘
            │             │             │
            └─────────────┼─────────────┘
                          ↓ 审核请求/交叉验证
                   ┌──────────────┐
                   │   AI-E 独立   │
                   │    审核       │
                   └──────────────┘
```

### 1.3 角色隔离规则

| 规则 | 说明 |
|------|------|
| 禁止角色叠加 | 同一个 AI Agent 实例**不能同时承担**执行角色（B/C/D）和审核角色（E） |
| 禁止自审 | AI-B 写的文档不能由 AI-B 自己审核，必须 AI-E 审核 |
| 审核优先 | AI-E 的审核意见优先级高于执行角色的初始输出 |
| 负责人中立 | AI-A 协调但不代替专业角色做技术决策 |

## 2. 任务单系统

### 2.1 任务单格式

每个分配给 AI 角色的工作必须通过标准任务单格式发起：

```markdown
# AI 任务单 — TASK-{NNN}

## 基本信息
| 字段 | 值 |
|------|-----|
| 任务编号 | TASK-001 |
| 指派角色 | AI-D |
| 创建人 | AI-A |
| 创建日期 | 2026-10-26 |
| 截止日期 | 2026-11-02 |
| 优先级 | P0 / P1 / P2 / P3 |
| 关联 WBS | 5.0.2 |
| 关联基线 | BL-3 |

## 任务描述
（明确说明要做什么，输入是什么，不做什么）

## 输入资料清单
- [ ] doc1.md（路径）
- [ ] doc2.md（路径）

## 输出要求
- [ ] 输出物 1：文件路径 + 格式
- [ ] 输出物 2：文件路径 + 格式

## 约束条件
- 技术约束：...
- 时间约束：...

## 验收标准（由 AI-E 检查）
1. [ ] 标准 1
2. [ ] 标准 2

## 状态跟踪
| 阶段 | 日期 | 操作者 | 备注 |
|------|------|--------|------|
| 已分配 | 2026-10-26 | AI-A | |
| 进行中 | - | - | |
| 提交审核 | - | - | |
| 审核通过 | - | AI-E | |
| 审核打回 | - | AI-E | 打回理由：... |
| 已完成 | - | AI-A | |
```

### 2.2 任务单生命周期

```
已分配 (Assigned)
    → 进行中 (In Progress)
    → 提交审核 (Submitted)
        ↓ AI-E 审核
        → 审核通过 (Approved) → 已完成 (Done)
        → 审核打回 (Rejected) → 进行中（修改）
        → 需要信息 (Need Info) → 已分配（补充）
```

### 2.3 任务单优先级定义

| 优先级 | 响应时间 | 说明 |
|--------|----------|------|
| P0 紧急 | 4h 内 | 安全相关、阻塞关键路径 |
| P1 高 | 24h 内 | 关键路径工作包、阶段门前 |
| P2 中 | 72h 内 | 非关键路径、常规任务 |
| P3 低 | 5d 内 | 优化建议、文档补充 |

## 3. CAD 操作反馈要求

### 3.1 Fusion 360 操作必须记录

AI-D 在 Fusion 360 中执行任何建模操作时，必须生成**操作日志**，包含：

| 记录项 | 格式 | 示例 |
|--------|------|------|
| 操作时间 | ISO 8601 | 2026-10-26T14:30:00+08:00 |
| 操作类型 | 枚举 | CreateBody / EditFeature / DeleteComponent |
| 对象标识 | Component Name | `Main Housing v1.2` |
| 参数值 | 键值对 | `length=120mm, width=45mm` |
| 依赖基线 | Git tag / Fusion version | BL-3 / Team Hub v23 |
| 关联任务 | TASK-NNN | TASK-042 |

### 3.2 CAD 输出给 AI-E 审核的反馈格式

AI-D 完成 CAD 操作后，必须向 AI-E 提交以下信息供审核：

```markdown
## CAD 反馈包 — FB-{NNN}

### 变更摘要
- 新增零件：N 个
- 修改零件：N 个
- 删除零件：N 个
- 参数变更清单：（列出关键参数前后值）

### Fusion 360 信息
- 文件路径：...
- Team Hub 版本号：v{NN}
- 发布状态：Draft / Released
- 快照链接：...

### Git 提交信息
- Commit hash：...
- 分支：feature/{branch-name}
- 关联 PR：#NNN

### 待审核清单（AI-E 检查项）
- [ ] 参数可驱动性
- [ ] 干涉检查结果
- [ ] 公差链完整性
- [ ] 与 PRS 需求的一致性
- [ ] 材料标注正确性
```

### 3.3 AI-E 对 CAD 的审核项

| 审核项 | 检查方法 | 通过标准 |
|--------|----------|----------|
| 全参数驱动 | AI-D 演示参数修改后全模型更新 | 所有关键参数响应正确 |
| 无硬编码尺寸 | 检查是否有不可修改的常量尺寸 | 100% 参数化 |
| 组件命名规范 | 对照命名规则 CM-001 | 全部符合 |
| 干涉检查 | Fusion 干涉检查 + AI-E 独立复核 | 无功能性干涉 |
| 质量属性 | 质量、质心、转动惯量 | 在 PRS 约束内 |
| 公差与配合 | 关键配合公差是否标注 | 全部关键配合已标注 |
| 工程图规范 | GD&T、比例、标注完整性 | 符合 ASME Y14.5 |

## 4. 审核状态机

### 4.1 AI-E 审核状态

AI-E 对任何执行角色输出的审核，状态定义如下：

```
┌─────────┐     ┌─────────────┐     ┌───────────┐
│ 待审核   │────→│ 审核进行中   │────→│ 审核通过 ✅│
│Pending  │     │ In Review   │     │ Approved  │
└─────────┘     └──────┬──────┘     └───────────┘
                       │
          ┌────────────┼────────────┐
          ↓            ↓            ↓
   ┌──────────┐  ┌──────────┐  ┌──────────┐
   │ 审核打回 ❌│  │ 需补充信息 │  │ 有条件通过 │
   │ Rejected │  │ Need Info │  │ Cond. OK │
   └────┬─────┘  └────┬─────┘  └────┬─────┘
        │             │             │
        ↓             ↓             ↓
   返回角色修改    等待补充后     记录条件后
                 重新进入审核    视为通过
```

### 4.2 审核意见模板

```markdown
## AI-E 审核报告 — REVIEW-{NNN}

| 字段 | 值 |
|------|-----|
| 审核编号 | REVIEW-015 |
| 被审对象 | TASK-042 输出 |
| 审核角色 | AI-E |
| 审核日期 | 2026-10-26 |
| 总体结论 | ✅ 通过 / ⚠️ 有条件通过 / ❌ 打回 |

### 详细检查结果

| 检查项 | 结果 | 证据/说明 |
|--------|------|-----------|
| 参数可驱动 | ✅ | 修改 length 后整机更新正确 |
| 干涉检查 | ✅ | Fusion 报告无干涉 |
| 公差链 | ❌ | 缺少轴承配合公差 |
| PRS 一致性 | ✅ | 符合 PR-012 质量约束 |

### 问题清单（如有）

| 编号 | 严重度 | 问题描述 | 建议修改 |
|------|--------|----------|----------|
| ISSUE-01 | 高 | 轴承配合缺少公差标注 | 添加 H7/g6 配合 |
| ISSUE-02 | 低 | 零件命名缩写不统一 | 改为全拼 |

### 行动项

| 编号 | 行动 | 责任人 | 截止日期 |
|------|------|--------|----------|
| ACTION-01 | 添加轴承配合公差 | AI-D | 2026-10-27 |
| ACTION-02 | 统一命名 | AI-D | 2026-10-27 |

### 后续流程
- [ ] AI-D 修改后重新提交
- [ ] AI-E 复审（可简化）
- [ ] AI-A 关闭任务
```

### 4.3 审核失败升级机制

| 连续打回次数 | 处理 |
|--------------|------|
| 1-2 次 | 正常修改流程 |
| 3 次 | AI-A 介入协调，分析根因 |
| 4 次 | 发起人介入，考虑换方案或人工审核 |

## 5. AI 输出标注规则

### 5.1 必须标注的 AI 输出

所有 AI Agent 生成的内容必须带上**来源标注**，格式：

```markdown
<!-- AI 生成标注 -->
> **内容来源**：AI-{角色代号}，任务单 TASK-{NNN}，日期 {YYYY-MM-DD}
> **审核状态**：✅ AI-E 已审核 / ⚠️ 待审核 / ❌ 有打回
<!-- 标注结束 -->
```

### 5.2 禁止事项

| 禁止行为 | 后果 |
|----------|------|
| AI 自行修改已冻结基线 | 直接触发变更控制 + R-016 风险升级 |
| AI 输出不标注来源 | AI-E 必须打回，不计入完成 |
| AI 执行角色代替审核角色做审核 | 审核无效，必须重新由 AI-E 执行 |
| AI 生成虚假测试数据或仿真结果 | 最高优先级 CAPA |
| AI 在没有输入的情况下"假设"关键参数 | 该输出不得作为设计输入 |

## 6. AI 特定安全措施

### 6.1 参数确认机制

AI 输出的任何**关键设计参数**（如电机选型、配合公差、频率、冲击力）必须经过以下三重确认：

1. **AI-C 机械分析** —— 理论计算支撑
2. **AI-D CAD 验证** —— 建模中参数响应正确
3. **AI-E 独立审核** —— 对照 PRS 检查

### 6.2 AI 幻觉防护

| 风险类型 | 防护措施 |
|----------|----------|
| 虚构标准号 | AI-E 对照法规清单 (9.0.1) 交叉验证 |
| 虚构材料属性 | 必须引用具体材料库来源（MatWeb、CES） |
| 虚构竞品数据 | 必须附搜索链接或数据来源 |
| 虚构 FMEA 条目 | AI-E 必须逐条确认故障模式是否合理 |

### 6.3 人机分界面

以下事项**必须由人工确认**，AI 不能独立决策：

1. 目标市场选择
2. 产品定位
3. 重大技术路线选择（如排除某方案）
4. 发起人决策请求的响应
5. 临床疗效声明
6. 最终发布批准
